# Proposal: [add | retire] — [agent name]

**Team:** [command | team-revenue | team-growth | team-ops]
**Date:** YYYY-MM-DD
**Proposed by:** [session / person]

## Problem

What's not getting done, or what's being done badly, that this addresses.
Cite a real instance if there is one (a PULSE finding, a missed task, a
recurring manual step) — not a hypothetical.

## If adding an agent

- **Mandate:** one or two sentences, same altitude as the other roster entries.
- **Tools it needs:** which connectors/APIs, and whether they're already
  available in this session or need to be newly connected.
- **Autonomy level:** read-only / draft-only / standing-with-limit
  (state the limit) / full standing. Default to the least autonomy that
  gets the job done — matches the guardrail in `crew/command/TEAM.md`.
- **Sunset condition:** what would make this agent's mandate obsolete or
  mean it should be re-scoped.

## If retiring an agent

- **Why:** superseded, mandate never materialized, tools never became
  available, or folded into another role.
- **What happens to its history:** its TEAM.md entry moves to
  `status: retired` with the date and reason; its spec file (if any) stays
  in the repo for the record rather than being deleted.

## Outcome

Left blank until reviewed. Filled in with what actually happened: adopted,
adopted with changes, or declined (and why).
